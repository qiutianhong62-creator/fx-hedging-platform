# Phase 12：美元应付网页

用户已确认：同一页面选择收到美元或支付美元；付款方向使用人民币成本与预算上限；切换方向保留金额、日期，清空远期交易、目标和结果。

## 行为与边界

- 初始为美元应收。选择美元应付后，真实报价表示买入美元的远期购汇价。
- 两种方向沿用同一自动概率 API。输入 exposure_type 决定方向；结果展示依 result_kind（cny_proceeds / cny_cost），不能从当前输入猜测旧结果的含义。
- 收款达标为收入 >= 目标；付款达标为成本 <= 预算。后端已有此逻辑，增加 API 回归案例确认。
- 后端差额保持“策略金额减不套保金额”。付款展示节省额时取反并交换区间上下界，正数表示节省、负数表示多花。不可用绝对值隐藏负号。
- 切换方向保留美元金额和到期日，交易重置为一行空值；清空目标、结果、错误与过期标志。旧方向的在途请求不能恢复结果。
- 编辑金额、日期或交易使已有结果过期，并清除旧目标概率。过期时不能仅重新计算目标；须先重新分析。编辑目标也清除原目标结果。
- 50%/90% 范围及尾部仍是概率范围与边界值，不是最大损失保证。超额套保继续允许并警示。
- 保持本地运行、USD/CNY、统一到期日、一笔或多笔远期。无需引入数据源或重写概率模型。

## 实现与验收

前端统一方向文案、请求与差额展示适配；输入和结果组件分别使用草稿方向和响应方向。请求序号隔离过期响应。

检查请求构造、双向切换清空、付款区间反向、跨零符号，以及接口中部分/全部/超额套保的预算概率。验证 100 万美元、50 万远期 6.8、到期汇率 7.0 时，不套保成本 700 万、策略 690 万、节省 10 万。

复验原有收款路径、构建和类型检查，并进行网页交互检查。实现后保留独立分支供用户审阅。
