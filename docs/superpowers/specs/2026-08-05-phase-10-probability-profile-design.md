# 第十阶段：完整汇率概率剖面设计

## 1. 背景

现有后端已经能够使用机构综合预测作为到期汇率分布的中心，使用 USD/CNY 历史年化波动率描述分布宽度，并返回：

- 预计到期汇率和预计人民币金额；
- 50% 常见汇率及金额范围；
- 90% 较宽汇率及金额范围；
- 用户目标的达标概率；
- 不套保与远期策略的概率比较。

这些结果能回答几个关键问题，但只给出了少数概括数字。前端尚无法展示“哪些汇率区间最可能”，用户也无法查看每个区间对应的人民币金额。

本阶段在不更换现有概率模型的前提下，把已有对数正态分布展开为一份适合前端图表与普通用户阅读的“概率剖面”。

## 2. 目标

在现有概率分析结果中新增 `probability_profile`，同时回答：

1. 到期汇率落入每个区间的概率是多少；
2. 到期汇率低于或高于某个区间边界的累计概率是多少；
3. 每个汇率区间对应的不套保人民币金额范围是多少；
4. 用户提交远期策略时，每个区间对应的远期策略金额范围是多少；
5. 主要范围之外的极低与极高汇率风险各有多大概率。

该结果为后续前端的区间概率柱状图、累计概率曲线和策略金额对比图提供直接数据。

## 3. 非目标

本阶段不包含：

- 更换对数正态分布或引入蒙特卡洛随机模拟；
- 根据多家机构的预测分歧动态修改波动率；
- 新增机构预测数据源；
- 期权策略的金额曲线；
- 前端图表与页面实现；
- 多到期日策略；
- 向用户声称模型结果是市场保证或投资建议。

## 4. 方案比较与决策

### 4.1 展示内容

考虑过三种方式：

1. 只返回区间概率；
2. 只返回低于或高于边界的累计概率；
3. 同时返回区间概率与累计概率。

决定采用第三种。区间概率更直观，累计概率则方便回答“高于或低于某一汇率的概率”。两者共用同一组区间边界，不需要重复计算。

### 4.2 区间划分

考虑过三种方式：

1. 固定每 0.05 或 0.10 一段；
2. 根据当次概率分布自动选择主要范围，再分成固定数量的等宽区间；
3. 使每个区间拥有相同概率。

决定采用第二种。固定汇率步长无法同时适应短期低波动和长期高波动。等概率分段又会导致每一格的概率都相同，不利于用户看出概率集中在哪里。

## 5. 用户逻辑链条

```text
用户输入敞口、到期日、目标和远期策略
                    │
                    ▼
        获取机构综合预测与历史波动率
                    │
                    ▼
           建立到期汇率概率分布
                    │
                    ▼
      取主要范围并自动分成20个等宽区间
                    │
                    ▼
       计算区间概率与边界累计概率
                    │
                    ▼
   换算不套保金额与远期策略金额范围
                    │
                    ▼
       返回主要区间、左尾和右尾风险
```

## 6. 概率剖面计算

### 6.1 主要范围

第一版使用：

- 主要范围下界：P1；
- 主要范围上界：P99；
- 主要区间数量：20；
- 主要范围理论概率：98%；
- 左尾理论概率：1%；
- 右尾理论概率：1%。

P1 和 P99 由现有 `LognormalDistribution.quantile()` 解析计算，不通过随机抽样估计。

### 6.2 等宽区间

```text
core_lower = quantile(0.01)
core_upper = quantile(0.99)
bucket_width = (core_upper - core_lower) / 20
```

系统生成 21 个边界，从而组成 20 个连续、不重叠且无空缺的主要区间。

数学计算使用未舍入的浮点边界。前端未来可根据展示需要保留小数位，不得将已展示舍入的数字送回后端重新计算。

### 6.3 区间概率

对于下界 `lower` 和上界 `upper`：

```text
interval_probability = cdf(upper) - cdf(lower)
probability_below_upper = cdf(upper)
probability_above_upper = 1 - cdf(upper)
```

因为到期汇率使用连续分布，边界使用严格大于还是大于等于不会改变概率数值。

系统不返回“到期汇率恰好等于某一个点的概率”。在连续分布中，单个精确点的概率为零；概率密度也不等于用户可直接理解的概率。

### 6.4 左尾与右尾

```text
lower_tail_probability = cdf(core_lower)
upper_tail_probability = 1 - cdf(core_upper)
```

左尾表示汇率低于 P1，右尾表示汇率高于 P99。它们是开放区间，因此后端不伪造有限的金额最大值或最小值。

每个尾部只返回：

- 方向：`below` 或 `above`；
- 边界汇率；
- 尾部概率；
- 不套保在边界汇率下的人民币金额；
- 如果存在远期策略，返回策略在边界汇率下的人民币金额。

## 7. 金额换算

### 7.1 不套保

每个区间的上下界继续调用现有不套保现金流公式。不套保结果根据敞口类型表示为：

- 美元应收或持有美元：人民币收入；
- 美元应付：人民币成本。

### 7.2 远期策略

每个边界汇率继续调用现有 `scenario_amounts_at_spot()`，不复制远期现金流公式。

对每个区间，分别计算下界金额与上界金额，然后使用：

```text
minimum_amount_cny = min(amount_at_lower, amount_at_upper)
maximum_amount_cny = max(amount_at_lower, amount_at_upper)
```

不根据汇率方向猜测金额方向。这能正确处理足额套保、部分套保与超额套保。

## 8. 后端分层

```text
LognormalDistribution
└─ 只负责分位数和累计概率
          │
          ▼
概率剖面生成器
├─ 生成21个边界
├─ 生成20个区间
├─ 计算区间与累计概率
└─ 生成左右尾部
          │
          ▼
业务金额适配层
├─ 不套保金额
└─ 远期策略金额
          │
          ▼
现有手动与自动概率响应
```

概率剖面生成器不访问网络，不理解 ING、MUFG 或 FRED，也不理解应收、应付和远期。它只接收已构建的概率分布并返回汇率边界与概率。

业务金额适配层在这些边界上调用已验证的现金流计算器。未来新增期权时，只需新增期权金额适配，不改动概率剖面。

## 9. 响应结构

### 9.1 不套保概率剖面

在 `NoHedgeProbabilityResponse` 顶层新增必定存在的 `probability_profile`：

```text
probability_profile
├─ core_lower_spot
├─ core_upper_spot
├─ core_probability
├─ bucket_count
├─ intervals[20]
│  ├─ lower_spot
│  ├─ upper_spot
│  ├─ interval_probability
│  ├─ probability_below_upper
│  ├─ probability_above_upper
│  ├─ minimum_amount_cny
│  └─ maximum_amount_cny
├─ lower_tail
│  ├─ direction = below
│  ├─ boundary_spot
│  ├─ probability
│  └─ boundary_amount_cny
└─ upper_tail
   ├─ direction = above
   ├─ boundary_spot
   ├─ probability
   └─ boundary_amount_cny
```

### 9.2 远期策略概率剖面

`ForwardStrategyProbabilityResponse` 同样新增 `probability_profile`。每个区间中的金额部分分为：

```text
no_hedge
├─ minimum_amount_cny
└─ maximum_amount_cny

forward_strategy
├─ minimum_amount_cny
└─ maximum_amount_cny
```

尾部边界金额也分别返回 `no_hedge_amount_cny` 与 `forward_strategy_amount_cny`。

### 9.3 接入现有接口

不新增独立 HTTP 接口。概率剖面直接加入：

- `POST /api/v1/analysis/no-hedge/probability`；
- `POST /api/v1/analysis/no-hedge/automatic-probability`；
- `POST /api/v1/analysis/forward-strategy/automatic-probability`。

现有请求字段不变。现有响应字段全部保留，`probability_profile` 是新增的顶层字段。

自动不套保响应继承手动不套保响应，自动远期响应继承远期概率响应，因此自动接口可以自然获得同一份概率剖面，不需要在外部数据编排服务中重复生成。

## 10. 精度与不变量

- 后端计算全程使用未展示舍入的汇率和概率。
- 概率使用 0 到 1 的浮点数，前端负责显示为百分比。
- 金额继续使用现有现金流计算器的舍入规则。
- 20 个区间与两个尾部的概率之和在浮点容差内等于 1。
- 累计低于概率随汇率边界单调不降。
- 累计高于概率随汇率边界单调不升。
- 每个区间的低于概率与高于概率在浮点容差内互为补数。
- 区间连续、不重叠、不缺失。
- 相同输入必须返回相同结果。

## 11. 外部数据与失败处理

本阶段不改变外部数据责任边界：

- 机构综合预测继续提供分布中心；
- FRED 历史市场数据继续提供年化波动率；
- 手动概率接口继续使用用户提交的假设参数；
- 自动概率接口不在外部数据失败时暗中使用虚构默认值。

无法构建概率分布、无法计算分位数或出现非有限数值时，继续使用现有概率计算错误，不返回部分伪造剖面。

## 12. 模型说明

自动响应继续保留并适用以下提醒：

```text
这是模型估算，不是对未来汇率的保证。
分布中心来自机构综合预测。
分布宽度主要参考历史波动率。
极端事件可能超出模型展示的常见范围。
本平台结果仅用于教学和风险分析，不构成交易或套保建议。
```

概率剖面只是将同一个模型的结果展示得更完整，不代表数据精细度提高后，预测本身也同比例变得更准确。

## 13. 性能与可维护性

一次请求只需要生成 21 个主要边界并对它们计算现金流。这不是大规模随机模拟，对现有 FastAPI 服务的计算负担很小。

概率边界在单次请求中只生成一次。不套保与远期策略共用这组边界，确保两种方案的金额在同一市场情景下比较。

## 14. 测试设计

### 14.1 概率剖面单元测试

- 必须生成 20 个主要区间。
- 第一个区间从 P1 开始，最后一个区间在 P99 结束。
- 相邻区间的上下界完全衔接。
- 每个区间概率等于两个累计概率之差。
- 区间概率与左右尾概率合计等于 1。
- 累计低于概率单调不降，累计高于概率单调不升。
- 短期、长期、低波动和高波动参数都可以生成有限结果。
- 相同输入生成完全相同的剖面。

### 14.2 不套保测试

- 每个区间都包含金额范围。
- 应收、应付和持有美元的金额均复用现有现金流公式。
- 左右尾都返回边界金额，但不返回伪造的封闭金额范围。
- 手动概率 API 响应包含概率剖面。

### 14.3 远期策略测试

- 区间同时返回不套保与远期策略金额范围。
- 部分套保、足额套保和超额套保都覆盖。
- 超额套保时金额上下限不会写反。
- 足额套保的策略金额在各区间保持固定。
- 不套保与远期策略必须使用同一组汇率边界。

### 14.4 自动分析与回归测试

- 不套保自动 API 使用机构综合预测与 FRED 波动率生成剖面。
- 远期策略自动 API 使用同一自动市场数据生成剖面。
- 响应中原有机构明细、权重、历史数据摘要与限制说明全部保留。
- 外部数据错误语义保持不变。
- 现有 262 项后端测试继续通过。

## 15. 手工验收

实现后在 FastAPI `/docs` 中分别测试：

1. 一笔不套保的美元应收；
2. 一笔部分远期套保；
3. 一笔足额远期套保；
4. 一笔超额远期套保。

验收时检查：

- 是否返回 20 个主要区间和 2 个尾部；
- 区间概率与尾部概率是否合计约 100%；
- 累计概率是否方向正确；
- 汇率区间是否连续；
- 不套保与远期金额是否能用边界汇率人工复算；
- 足额套保的金额范围是否缩小为固定值。

## 16. 验收标准

本阶段完成时，用户无需新增任何输入，就可以在现有概率分析响应中获得：

- 由 P1 至 P99 组成的 20 个等宽汇率区间；
- 每个区间的发生概率；
- 每个区间上边界的低于与高于累计概率；
- 每个区间的不套保金额范围；
- 存在远期策略时的策略金额范围；
- P1 以下与 P99 以上的尾部风险概率及边界金额。

概率计算使用现有解析对数正态模型，不使用随机模拟。所有现有接口输入和结果字段继续保留，新结构能够直接支持后续前端概率图表，也为期权金额曲线预留清晰扩展点。
