# 第十一阶段：概率分析首页设计

## 1. 背景

当前首页主要在浏览器中根据用户手动填写的假设到期汇率计算收益曲线，与第八至第十阶段已经完成的 Python 概率后端没有连接。现有页面强调单点情景和自由交易搭建器，也不再符合当前产品首先验证“美元应收敞口＋远期结汇概率分析”的目标。

本阶段将重做首页，使它直接调用 Python 后端的真实自动概率接口。用户输入美元应收敞口、到期日和一笔或多笔真实远期报价后，网页展示机构预测、历史波动率、完整汇率概率区间，以及不套保与远期策略的人民币收款对比。

## 2. 已确认的产品决策

- 重做现有首页，不在旧首页下方追加一个孤立模块。
- 第一版只支持 USD/CNY 的美元应收敞口和远期结汇。
- 第一版在用户电脑本地运行，浏览器直接连接本地 Python 后端。
- 网页默认包含一笔远期，用户可以继续添加多笔远期。
- 所有远期使用同一个分析到期日，但可以有不同名义金额和报价。
- 远期总额可以超过敞口；系统不修改用户数据，但明确显示过度套保风险。
- 先完成第一次分析，再让用户填写目标人民币金额并重新计算达标概率。
- 结果采用“数据优先”布局，详细概率表位于辅助图表之前。
- 不套保和远期策略在同一行直接比较。
- 默认显示概率最高的 8 个核心区间，并允许展开完整 20 个核心区间和两个尾部区间。
- 数据来源区域始终展示机构、更新时间、权重和可用状态。
- 旧页面依赖的策略计算文件暂不删除，但旧页面组件不再从新首页渲染。

## 3. 范围

### 3.1 本阶段包含

- 新的概率分析首页。
- 为远期概率区间响应补充由 Python 计算的策略差额范围。
- 多笔远期输入、删除和前端校验。
- 与 `POST /api/v1/analysis/forward-strategy/automatic-probability` 的真实连接。
- 不含目标金额的首次分析。
- 填写目标金额后的二次分析。
- 机构预测和 FRED 历史波动率来源展示。
- 模型摘要、概率区间表、目标达标比较、辅助概率图和风险说明。
- 加载、校验、降级数据源、后端未连接和后端错误状态。
- 本地开发所需的受限 CORS 配置。
- 前端单元测试、渲染测试和真实本地联调说明。

### 3.2 本阶段不包含

- 美元应付、持有美元或其他货币对。
- 期权、掉期、定存或跨产品复合策略。
- 多个不同到期日。
- 用户登录、策略保存、数据库或历史分析记录。
- Python 后端互联网部署。
- 机构预测模型或概率模型本身的修改。
- 自动生成套保建议或声称某个策略是最优策略。

## 4. 用户流程

```text
填写美元应收金额、到期日和远期交易
                    ↓
前端检查必填项、数值和过度套保
                    ↓
调用本地 Python 自动远期概率接口（target_cny = null）
                    ↓
后端读取 ING、MUFG 和 FRED 历史波动率
                    ↓
首页展示数据来源、摘要和概率对比表
                    ↓
用户可填写目标人民币金额
                    ↓
使用相同输入重新调用接口（携带 target_cny）
                    ↓
增加不套保与远期策略的目标达标概率比较
```

修改敞口、日期或任何远期交易后，旧结果标记为需要重新分析，不在后台静默自动请求。这样可以避免用户每输入一个数字就触发外部数据抓取。

## 5. 页面结构

首页从上到下包含以下区域。

### 5.1 页面标题

用一句大白话说明用途：输入真实远期报价，比较不套保与远期策略在不同到期汇率区间下的人民币收款结果。第一版范围标签明确写出“USD/CNY · 美元应收 · 同一到期日”。

### 5.2 分析条件

必填输入：

- 美元应收金额 `notional_usd`；
- 到期日 `maturity_date`；
- 至少一笔远期的美元金额 `forward_legs[].notional_usd`；
- 每笔远期的真实结汇报价 `forward_legs[].forward_rate`。

固定但不要求用户选择的请求字段：

- `currency_pair = "USD/CNY"`；
- `exposure_type = "usd_receivable"`；
- 首次分析时 `target_cny = null`。

每笔远期显示序号、金额、报价和删除按钮。页面提供“添加一笔远期”。仅剩一笔时不允许删到零笔，而是提示至少需要一笔远期。

输入区同时计算并展示：

- 远期总金额；
- 套保覆盖比例；
- 未套保金额；
- 过度套保金额。

远期总额超过敞口时仍允许提交，但输入区和结果区均显示红色过度套保警告。

### 5.3 数据来源

分析成功后始终显示：

- ING 和 MUFG 是否参与本次预测；
- 每家机构匹配到用户到期日的预测汇率；
- 每家机构的实际权重；
- 来源更新时间、抓取时间和缓存状态；
- 综合方式是等权共识还是单一来源降级；
- FRED 历史波动率、观察窗口和数据更新时间。

单一机构不可用时，来源区域使用黄色状态，不把降级结果伪装成完整共识。两家机构都不可用时不显示概率结果。

### 5.4 结果摘要

概率表之前放置紧凑摘要，不使用夸张的“推荐”或“保证”语言。摘要至少包含：

- 模型预计到期汇率；
- 最可能出现的汇率区间及其区间概率；
- 不套保预计人民币收款；
- 远期策略预计人民币收款；
- 不套保和远期策略各自的 50% 常见金额范围；
- 不套保和远期策略各自的 90% 较宽金额范围。

“最可能区间”通过 `probability_profile.intervals` 中最高的 `interval_probability` 得出，不将某个精确汇率点描述为具有非零概率。

### 5.5 核心概率表

核心表格在同一行比较两种策略：

| 列 | 内容 |
|---|---|
| 到期汇率区间 | `lower_spot` 至 `upper_spot` |
| 发生概率 | `interval_probability` |
| 累计概率 | 低于本行上限的 `probability_below_upper`，并可用次要文字补充高于上限的概率 |
| 不套保收款范围 | `no_hedge.minimum_amount_cny` 至 `maximum_amount_cny` |
| 远期策略收款范围 | `forward_strategy.minimum_amount_cny` 至 `maximum_amount_cny` |
| 策略差额 | 后端新增的 `strategy_minus_no_hedge` 准确差额范围，明确为区间而不是单点值 |

现有区间响应分别返回不套保金额范围和远期金额范围，但两者在过度套保时可能随汇率朝相反方向变化。前端不能用两个独立范围直接相减，否则可能把不对应同一汇率端点的上下界配在一起。因此 Python 后端需要在每个 `ForwardProbabilityProfileInterval` 中增加：

```text
strategy_minus_no_hedge.minimum_amount_cny
strategy_minus_no_hedge.maximum_amount_cny
```

该字段由现有远期策略公式在区间两个汇率端点上计算并排序。它是向后兼容的响应扩展，不改变已有请求和其他字段。

默认表格先按 `interval_probability` 选出概率最高的 8 行，再按 `lower_spot` 从低到高排列。点击“查看完整分布”后，显示全部 20 行，并在首尾加入：

- 低于 `lower_tail.boundary_spot` 的左尾区间；
- 高于 `upper_tail.boundary_spot` 的右尾区间。

尾部只有边界金额而不是封闭金额范围，页面不能虚构无穷区间另一端的金额。尾部行使用“低于”和“高于”表述，并标记为低概率极端情景。

### 5.6 目标金额

首次结果出现后，显示独立目标金额区域。用户可以输入 `target_cny` 并点击“计算达标概率”。前端使用完全相同的敞口、到期日和远期腿重新调用同一接口，仅新增目标金额。

二次结果显示：

- 不套保达到目标的概率和未达到概率；
- 远期策略达到目标的概率和未达到概率；
- 远期策略相对不套保提高或降低的百分点；
- 目标对应的临界汇率；
- 当临界汇率不存在时，用大白话解释策略金额是否始终达到或始终不能达到目标。

目标结果是模型估算，不使用“必定达标”“保证收益”等措辞。

### 5.7 辅助图表

图表排在概率表之后。第一版展示汇率区间概率分布：

- 横轴为 USD/CNY 到期汇率区间；
- 纵轴为区间发生概率；
- 默认突出概率最高的区间；
- 可标记预计到期汇率、50% 常见区间和 90% 较宽区间；
- 图表与表格使用同一份 API 返回数据，不在前端重新计算分布。

图表是辅助解释，不替代详细数据表。图表必须有文本标题、坐标含义和可访问的文字摘要。

### 5.8 风险和局限

页面底部以及相关结果旁展示：

- 机构预测可能与实际汇率明显不同；
- 历史波动率不保证代表未来波动；
- 结果用于风险分析，不构成银行报价、交易建议或收益保证；
- 过度套保会让超过实际敞口的部分形成反向风险；
- 来源降级或使用陈旧缓存时的具体状态。

## 6. 前端结构

首页负责组织流程，金融数据转换和展示拆成独立单元：

```text
app/page.tsx
  ├─ AnalysisInputPanel
  │    └─ ForwardLegEditor
  ├─ DataSourceStatus
  ├─ AnalysisSummary
  ├─ ProbabilityComparisonTable
  ├─ TargetAnalysisPanel
  ├─ ProbabilityDistributionChart
  └─ RiskNotices

lib/api/forwardProbability.ts
  ├─ 请求与响应 TypeScript 类型
  ├─ API 基础地址
  ├─ 请求函数
  └─ 后端错误标准化

lib/analysis/probabilityProfile.ts
  ├─ 选择概率最高的 8 个区间
  ├─ 恢复汇率升序
  ├─ 读取后端提供的金额差额区间
  └─ 格式化尾部展示数据
```

组件只负责一类事情。API 模块不包含界面逻辑；展示转换模块不重新实现 Python 概率模型；页面不直接散落 `fetch` 调用。

## 7. 前后端连接

第一版本地请求地址默认为：

```text
http://127.0.0.1:8000/api/v1/analysis/forward-strategy/automatic-probability
```

API 基础地址通过前端环境配置集中管理，默认指向 `http://127.0.0.1:8000`。未来部署时只替换该配置或在服务端增加代理，不修改页面组件。

浏览器直连不同端口会触发跨域限制，因此 FastAPI 需要加入受限 CORS：仅允许本地前端实际使用的开发地址，例如 `http://localhost:3000` 和 `http://127.0.0.1:3000`。不使用无条件的 `allow_origins=["*"]`。

首次请求示例：

```json
{
  "currency_pair": "USD/CNY",
  "exposure_type": "usd_receivable",
  "notional_usd": 1000000,
  "maturity_date": "2026-12-31",
  "target_cny": null,
  "forward_legs": [
    { "notional_usd": 300000, "forward_rate": 6.8 },
    { "notional_usd": 200000, "forward_rate": 6.75 }
  ]
}
```

目标分析复用同一请求，仅把 `target_cny` 改为正数。

## 8. 页面状态

页面采用明确状态而不是多个互相冲突的布尔值：

- `idle`：尚未分析；
- `loading_initial`：首次分析中；
- `success`：首次分析成功；
- `loading_target`：目标概率重新计算中，保留已有结果；
- `validation_error`：前端或后端字段校验失败；
- `connection_error`：本地 Python 后端未连接；
- `analysis_error`：机构、市场数据或概率计算失败。

用户修改基础输入后，已有结果保留但显示“输入已变化，请重新分析”，目标结果同时失效。用户点击重新分析后才发送新请求。

## 9. 校验与错误处理

### 9.1 前端校验

- 敞口必须大于 0；
- 到期日必须晚于当天；
- 至少保留一笔远期；
- 每笔远期金额和报价必须大于 0；
- 目标金额如填写必须大于 0；
- 远期总额超过敞口只警告，不阻止请求。

### 9.2 后端错误映射

- HTTP 422 的 `validation_error` 映射到对应字段；
- `probability_calculation_error` 显示模型无法计算的说明；
- forecast 或 market-data 错误显示后端提供的中文消息；
- 网络失败或连接被拒绝显示“Python 服务未连接”，保留全部输入；
- 非预期响应显示通用错误和重试按钮，不向用户直接输出堆栈信息。

请求进行中禁用对应提交按钮，避免重复请求。目标请求失败时保留首次分析结果。

## 10. 显示规则

- 人民币金额以“万元”为主，悬停或辅助文字提供完整元金额；
- 美元金额采用千位分隔，不擅自取整请求数据；
- 汇率保留四位小数，区间表可根据边界精度保持一致；
- 概率以百分比显示，至少保留一位小数，小概率不能直接显示为 0%；
- 差额使用“远期策略－不套保”的统一口径；
- 正差额表示该汇率区间内远期策略收款更高，负差额表示机会成本；
- 颜色不能是唯一信息载体，必须同时使用正负号和文字标签。

## 11. 测试设计

### 11.1 展示转换单元测试

- 从 20 个核心区间中选出概率最高的 8 个；
- 选出后按 `lower_spot` 升序展示；
- 概率并列时使用稳定且可预测的排序；
- 完整模式正确加入两个尾部区间；
- 尾部不生成虚假的无限金额范围；
- 金额差额区间直接使用后端字段，不从两个独立金额范围重新相减；
- 百分比、汇率和金额格式符合显示规则。

### 11.2 API 模块测试

- 首次请求发送 `target_cny: null`；
- 多笔远期保持用户输入顺序并正确序列化；
- 目标请求只改变 `target_cny`；
- 422 字段错误、连接失败和服务错误被标准化；
- API 基础地址集中读取而不是写死在组件中。

### 11.3 组件和页面测试

- 默认一笔远期，可添加和删除但不能删到零笔；
- 过度套保显示警告但仍可提交；
- 加载时防止重复提交；
- 成功结果默认显示 8 行，展开后显示 20 行和两个尾部；
- 单一机构来源时显示降级状态和实际权重；
- 修改基础输入后提示重新分析并使目标结果失效；
- 目标请求失败不清除首次结果；
- 表格与输入在窄屏下可用，表头、字段标签和错误提示可被辅助技术读取。

### 11.4 本地联调

1. 启动 Python 后端并确认 `/health` 可用；
2. 启动前端；
3. 输入美元应收金额、未来到期日和两笔远期；
4. 验证真实机构来源、历史波动率和概率表；
5. 展开完整分布并核对 20 个核心区间和两个尾部；
6. 输入目标金额并验证两种达标概率；
7. 停止后端，确认页面保留输入并给出连接提示；
8. 输入过度套保组合，确认警告和结果均正常出现。

### 11.5 后端回归测试

- 部分套保、完全套保和过度套保均返回正确的区间差额上下界；
- 每个差额端点都对应同一汇率端点下的“远期策略－不套保”；
- 原有自动远期概率接口字段保持兼容；
- 完整 Python 测试套件继续通过。

## 12. 验收标准

- 新首页不再要求用户手动填写假设到期汇率或情景上下限。
- 用户可以输入一笔或多笔真实远期报价并得到真实后端结果。
- 页面始终能说明机构预测和历史波动率来自哪里。
- 不套保和远期策略在同一概率区间行中可直接比较。
- 策略差额由 Python 后端计算，过度套保时不会在前端错误组合区间上下界。
- 默认 8 行与完整 22 行展示规则正确且可测试。
- 用户在看到首次结果后可以增加目标金额并比较达标概率。
- 过度套保被允许但有醒目警告。
- 单一来源降级、后端离线和全部来源失败均有明确且不误导的界面状态。
- 前端不复制 Python 概率算法，所有图表和表格来自同一次 API 返回。
- 现有 Python 后端测试继续通过，新增前端测试和构建检查通过。

## 13. 后续方向

完成本阶段并验证真实链路后，可以依次增加：

1. 将 Python 后端部署到互联网并替换本地 API 地址；
2. 增加美元应付方向；
3. 增加更多机构预测和可配置权重；
4. 把期权、掉期和定存接入同一概率比较框架；
5. 增加策略保存、版本比较和历史分析记录。
